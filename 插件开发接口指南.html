ExamAware 插件开发指南（API V2）

V2 是插件跟 ExamAware 桌面端打交道的唯一方式，同时也是推荐方式。写插件的时候，所有入
口函数和类型都从 @dsz-examaware/plugin-sdk 里拿，调用宿主能力走
ctx.api.<领域>.<方法>()。不要直接 import Electron，也别碰 window.api，更不要自己
拼 IPC 字符串。

这篇文章是快速上手用的。参数和返回值的准确定义看
contracts.ts 里的 TypeScript 类型，
那个才是最终依据。

1. 写一个最小的插件

Main 进程入口适合搞文件操作、网络请求、后台服务、HTTP 路由这些东西：

import { defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    const app = await ctx.api.app.info();
    ctx.logger.info(`跑在 ExamAware ${app.version} 上`);
  }
});

Renderer 进程入口适合搞页面、菜单、编辑器面板、播放器工具栏这些 UI 类的活：

import { defineRendererPlugin } from '@dsz-examaware/plugin-sdk';

export default defineRendererPlugin({
  activate(ctx) {
    return ctx.api.ui.home.register({
      id: 'open-editor',
      label: '打开编辑器',
      icon: 'edit',
      action: () => ctx.api.windows.openEditor()
    });
  }
});

然后在插件的 package.json 里声明 V2 入口、权限、以及 renderer 需要在哪些窗口激
活：

{
  "name": "@examaware-plugins/my-plugin",
  "version": "1.0.0",
  "examaware": {
    "apiVersion": 2,
    "targets": {
      "main": "./dist/main/index.cjs",
      "renderer": "./dist/renderer/index.mjs"
    },
    "permissions": ["player.start", "files.read", "ui.contribute", "windows.open"],
    "activation": {
      "rendererWindows": ["main", "editor", "player"]
    }
  }
}

rendererWindows 可以写 main、editor、player、settings、cast、
logs、plugin-store、tray、plugin。不写的话 V2 renderer 默认只在 main 窗
口激活。没有 renderer 入口就不写 renderer target，没有 main 入口同理。

2. 插件上下文

activate(ctx) 里你能拿到这些东西：

字段干嘛用的
ctx.api所有宿主 API 的入口，后面的调用都从它开始
ctx.plugin当前插件的名称、显示名、版本、API 版本
ctx.process当前入口跑在哪个进程：main 还是 renderer
ctx.logger自带插件前缀的 debug/info/warn/error 日志器
ctx.permissionsgranted、has()、require() 查权限用
ctx.initialSettings激活那一刻的初始设置快照，只读
ctx.scope统一管理资源释放的作用域，插件卸载时自动清理
ctx.window只有 renderer 里有，当前窗口的 id/kind/route

main 和 renderer 都有公共 API。只有 main 能注册 HTTP 路由和深链处理器，只有
renderer 能用到 ctx.api.ui。

3. API 速览

表格里的"权限"就是 manifest 里要写的东西。- 意思是这个不用额外声明。

app：应用信息和全局操作

方法权限用途
info()-拿到名称、版本、平台、是否打包版
getAutoStart()-看开机自启有没有开
setAutoStart(enabled)app.configure开关开机自启
quit()app.quit退出 ExamAware
if (ctx.permissions.has('app.configure')) {
  await ctx.api.app.setAutoStart(true);
}

写代码的时候建议用 PluginPermissions.App.Configure 这种常量来查权限，不用手写字
符串。manifest 里还是用表里列的那些字符串。

player：准备、开始、控制放映

不管你用哪种方式开始放映，最终都会进同一套流程：解析 → 规范化 → 校验 → 确认窗口准
备好 → 会话管理。

方法权限用途
prepare(source, options?)player.start只解析校验，不弹窗口
start(source, options?)player.start走统一的 PlayerSource 开始放映
startFromFile(path, options?)player.start + files.read从本地考试文件开始放
startFromConfig(config, options?)player.start从已经拼好的 ExamConfig 开始放
startFromJson(data, options?)player.start从一段 JSON 文本开始放
startFromUrl(url, options?)player.start + network.http下载远程配置然后放
getSession(id)player.observe拿到指定会话的句柄
listSessions()player.observe拿到所有会话的快照
onSessionChanged(listener)player.observe订阅会话状态变化

start 和 prepare 接受四种来源：

type PlayerSource =
  | { kind: 'file'; path: string }
  | { kind: 'config'; config: ExamConfig }
  | { kind: 'json'; data: string }
  | { kind: 'url'; url: string; headers?: Readonly<Record<string, string>> };

URL 指向本机或者局域网的时候，还要 network.local 权限，并且要传
allowLocalNetwork: true。常用的启动选项有这些：

  • replaceExisting：替换已有的放映，不新开会话。
  • waitForReady、readyTimeoutMs：等窗口准备好，可以设超时。
  • requestTimeoutMs、maxBytes、allowLocalNetwork：限制远程请求。
  • validation：传 ExamConfigValidationOptions 来调校验行为。
  • window.fullscreen/kiosk/alwaysOnTop/displayId：控制放映窗口的行为。
const prepared = await ctx.api.player.prepare(
  { kind: 'url', url: 'https://example.com/exam.json' },
  { validation: { allowEmptyExamInfos: false } }
);

if (!prepared.validation.valid) {
  ctx.logger.warn('考试配置有问题', prepared.validation.errors);
  return;
}

const session = await ctx.api.player.startFromConfig(prepared.config, {
  waitForReady: true,
  window: { fullscreen: true }
});
await session.focus();

PlayerSession 有 snapshot()、focus()、close()、replaceSource(source, options?)
和 dispose() 这些方法。控制会话要 player.control 权限；替换来源还要
player.start 加上对应的文件或网络权限。

exams：处理考试配置

方法权限用途
parse(input)-解析 JSON 文本，返回完整校验结果
validate(input, options?)-校验输入，成功的话给你类型化配置
normalize(config)-把合法配置整理成稳定结构
serialize(config, pretty?)-把配置转回 JSON 字符串
const result = ctx.api.exams.parse(json);
if (!result.valid || !result.config) {
  ctx.logger.warn('配置不对', result.errors);
  return;
}
const output = ctx.api.exams.serialize(ctx.api.exams.normalize(result.config), true);

files 和 dialogs：文件和系统对话框

API权限用途
files.open(options?)files.dialog选文件或目录，返回路径数组
files.save(options?)files.dialog选保存路径，取消的话返回 undefined
files.readText(path) / readBytes(path)files.read读文本或二进制
files.writeText(path, data) / writeBytes(path, data)files.write写文本或二进制
files.exists(path) / stat(path)files.read看看文件在不在，以及类型大小时间
files.watch(path, listener)files.watch监听文件变化，返回 Disposable
dialogs.message(options)ui.notify弹出系统消息框，拿到用户点了哪个
dialogs.openFile(options?) / saveFile(options?)files.dialog就是文件对话框，语义别名
const [path] = await ctx.api.dialogs.openFile({
  title: '选一个考试配置',
  filters: [{ name: 'JSON', extensions: ['json'] }]
});
if (path) {
  const result = ctx.api.exams.parse(await ctx.api.files.readText(path));
  ctx.logger.info('配置校验结果', result.valid);
}

settings：当前插件的设置

方法权限用途
get()-同步拿当前设置，只读
replace(settings)-整个替换
patch(partial)-浅合并一部分字段
reset()-恢复默认设置
onChanged(listener)-监听设置变化

给 defineMainPlugin<MySettings>() 或 defineRendererPlugin<MySettings>()
传个类型参数，所有方法都会在 IDE 里有自动补全。

interface MySettings {
  enabled: boolean;
  endpoint?: string;
}

export default defineMainPlugin<MySettings>({
  activate(ctx) {
    ctx.scope.add(
      ctx.api.settings.onChanged((settings) => {
        ctx.logger.info('enabled 变了', settings.enabled);
      })
    );
  }
});

windows：窗口导航和插件窗口

方法权限用途
open(options?)windows.open创建插件窗口，返回句柄
get(id)windows.manage按插件窗口 ID 拿到句柄
openMain()windows.open打开主界面
openEditor(path?)windows.open打开编辑器，可以直接载入文件
openSettings(page?)windows.open打开设置，可以指定页面
openCast() / openLogs() / openPluginStore()windows.open打开投送、日志、插件商店

插件窗口句柄有 focus()、close() 和 dispose()，操作句柄要 windows.manage 权限。

const window = await ctx.api.windows.open({
  id: 'preview',
  route: '/preview',
  title: '预览',
  width: 900,
  height: 640
});
ctx.scope.add(window);

commands 和 events：类型化的命令与事件

方法权限用途
commands.register(token, handler, options?)commands.register注册命令，返回 Disposable
commands.execute(token, args)commands.execute执行命令，拿到类型化结果
commands.has(token)-查当前进程有没有这个命令
events.on(token, listener) / once(...)events.subscribe订阅事件，持续或一次性
events.emit(token, payload)events.publish发布类型化的消息

token 建议定义在一个 main 和 renderer 都能 import 的 shared/contracts.ts 里：

import { createPluginTokens } from '@dsz-examaware/plugin-sdk';

const tokens = createPluginTokens('@examaware-plugins/my-plugin');

export const refreshCommand = tokens.command<{ force: boolean }, number>('refresh');
export const configChanged = tokens.event<{ revision: number }>('config-changed');
ctx.scope.add(
  ctx.api.commands.register(refreshCommand, async ({ force }) => (force ? 1 : 0), {
    title: '刷新插件数据'
  })
);
const revision = await ctx.api.commands.execute(refreshCommand, { force: true });
ctx.api.events.emit(configChanged, { revision });

记住：不要把 command ID、event ID、参数类型散落成裸字符串到处写。

notifications：应用内通知

方法权限用途
show(options)ui.notify弹一个 info/success/warning/error 通知，可设时长
await ctx.api.notifications.show({
  level: 'success',
  title: '导入好了',
  message: '考试配置校验通过了'
});

time：统一时钟和时间同步

方法权限用途
now()time.read拿经过同步偏移修正的当前时间戳
info()time.read拿偏移量、服务器、同步状态
synchronize()time.synchronize立刻执行时间同步
configure(config)time.configure更新同步配置，返回规范化结果
onChanged(listener)time.read监听同步状态变化

跟放映时钟保持同步的时候用 await ctx.api.time.now()，不要自己拼时间 IPC。

cast：局域网投送

方法权限用途
peers()cast.read列出发现的设备
localShares()cast.read列出本机共享的考试
peerShares(peerId)cast.read列出某台设备的共享
getPeerConfig(peerId, shareId?)cast.read读取对端共享的配置 JSON
send(peerId, source)cast.send把文件、配置、JSON 或 URL 发给设备
const [peer] = await ctx.api.cast.peers();
if (peer) {
  await ctx.api.cast.send(peer.id, { kind: 'config', config });
}

network：受控的网络请求

方法权限用途
request(url, options?)network.http发请求，拿状态码、响应头和二进制
getText(url, options?)network.http拿文本
getJson<T>(url, options?)network.http拿并解析成类型化的 JSON

请求选项支持 method、headers、body、timeoutMs、maxBytes 和
allowLocalNetwork。访问本机或内网还要 network.local。request() 的返回值里有
status、headers、body、text() 和 json<T>()。

interface RemoteStatus {
  online: boolean;
}

const status = await ctx.api.network.getJson<RemoteStatus>('https://example.com/status', {
  timeoutMs: 5_000,
  maxBytes: 64 * 1024
});

http：ExamAware 内置 HTTP 服务

方法进程权限用途
baseUrl()main/renderer-拿到当前服务的基址
configure(config)main/rendererhttp.configure更新服务配置
restart()main/rendererhttp.configure重启服务
registerRoute(route)仅 mainhttp.routes注册插件路由，返回 Disposable
ctx.scope.add(
  ctx.api.http.registerRoute({
    method: 'GET',
    path: '/plugins/my-plugin/status',
    summary: '插件状态',
    requireAuth: true,
    handler: ({ query }) => ({
      status: 200,
      body: { ok: true, detail: query.detail === '1' }
    })
  })
);

路由处理函数能拿到 method/path/query/headers/body，返回 status/headers/body，
都可以不写。路由注册只能写在 main 入口。

deepLinks：深链

方法进程权限用途
dispatch(url)main/rendererdeep-links.dispatch主动分派一个深链 URL
onOpened(listener)main/rendererevents.subscribe监听宿主收到的深链
register(path, handler)仅 maindeep-links.register注册路径处理器，返回 Disposable
ctx.scope.add(
  ctx.api.deepLinks.register('/my-plugin/open', async ({ query }) => {
    ctx.logger.info('打开项', query.id);
    return true;
  })
);

payload 里有 raw/scheme/host/pathname/query。处理器返回 true 表示"这事我处理了"。

logging：结构化日志

方法权限用途
createLogger(scope)-创建带子作用域的日志器
entries()logging.read读取日志条目

一般情况下直接用 ctx.logger 就够了。复杂插件可以用
ctx.api.logging.createLogger('sync') 分出独立的日志 channel。

plugins：插件状态和管理

方法权限用途
current()-同步拿当前插件信息
list()plugins.read列出所有插件和状态
enable(name) / disable(name) / reload(name)plugins.manage管理指定插件

插件信息里包含名称、显示名、版本、状态、是否启用、API 版本。

const installedPlugins = await ctx.api.plugins.list();

services：同进程服务和跨进程 RPC

方法权限用途
provide(token, service)services.provide在当前进程提供对象服务，返回 Disposable
use(token)services.consume在当前进程拿到服务对象
has(token)-查当前进程有没有这个服务
exposeRpc(token, service)services.provide暴露跨 main/renderer 调用的 RPC 服务
rpc(token)services.consume创建类型安全的 RPC 客户端代理

同进程服务可以包含函数，但不能直接跨 Electron 进程传递。跨 main/renderer 必须定
义 RPC token：

// shared/contracts.ts
import { createPluginTokens } from '@dsz-examaware/plugin-sdk';

const tokens = createPluginTokens('@examaware-plugins/my-plugin');

export interface DataService {
  load(id: string): Promise<{ value: string }>;
}

export const dataService = tokens.rpc<DataService>('data-service');
// main
ctx.api.services.exposeRpc(dataService, {
  async load(id) {
    return { value: `item:${id}` };
  }
});

// renderer：方法名、参数、返回值 IDE 全帮你检查
const data = await ctx.api.services.rpc(dataService).load('42');

createPluginTokens(namespace) 还能生成 .service<T>()、.command<A, R>()、
.event<T>() 和 .apiModule<T>()。普通插件一般不需要自定义宿主 API module。

ui：界面贡献（仅 renderer）

home/pages/settings/editor/menus 的注册要 ui.contribute 权限；播放器工具栏注册只
要 player.contribute。ui.editor.clearView() 不用额外权限。

方法用途
ui.home.register(item)注册主页操作入口
ui.pages.register(page)注册插件页面和路由
ui.settings.registerPage(page)注册设置页面
ui.editor.registerPanel(panel)注册编辑器面板
ui.editor.presentView(view)临时呈现一个编辑器视图
ui.editor.clearView(id?)清除一个或全部临时视图
ui.player.registerToolbarItem(item)注册播放器工具栏按钮
ui.menus.register(item)把类型化 command 注册为菜单项

组件可以直接传框架组件，也可以传返回组件的异步工厂函数：

await ctx.api.ui.settings.registerPage({
  id: 'general',
  label: '我的插件',
  icon: 'extension',
  order: 50,
  component: () => import('./MySettingsPage.vue')
});

home/pages/settings/editor/player/menus 分别在对应的宿主界面上才有意义。用
activation.rendererWindows 精确声明哪些窗口要加载 renderer，别让插件在不相关
的窗口里白跑。

4. 生命周期和资源清理

V2 的生命周期一共这些步骤：

  1. onLoad(ctx)：激活前准备。
  2. activate(ctx)：注册能力、启动插件。这个是必须的。
  3. onReady(ctx)：激活成功之后跑。
  4. deactivate(ctx)：卸载前停业务。
  5. 释放 activate 返回的函数或 Disposable，同时清空 ctx.scope。
  6. onUnload(ctx)：最终清理。
  7. onError(error, ctx)：生命周期出问题的时候收一个统一的 PluginApiError。

注册命令、事件、路由、UI 项这些 API 返回的都是 Disposable，宿主会自动把这些注
册项归到当前插件的作用域里。但你自己创建的定时器、观察器之类的，记得显式加到 scope：

export default defineMainPlugin({
  activate(ctx) {
    const timer = setInterval(() => ctx.logger.debug('滴'), 10_000);
    ctx.scope.defer(() => clearInterval(timer));

    ctx.scope.add(
      ctx.api.events.on(configChanged, ({ revision }) => {
        ctx.logger.info('revision', revision);
      })
    );
  }
});

ctx.scope.add(disposable) 接收 Disposable 或者清理函数；
ctx.scope.defer(fn) 就是帮你把任意清理函数包进作用域。重复释放也没事，安全的。

5. 权限和错误处理

默认就会给你 time.read、logging.read、plugins.read 和 events.subscribe。其
他的权限都要在 examaware.permissions 里写。写代码建议用常量做分支判断：

import { PluginApiError, PluginPermissions, defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    if (!ctx.permissions.has(PluginPermissions.Network.Http)) return;

    try {
      await ctx.api.network.getText('https://example.com/ping');
    } catch (error) {
      const apiError = PluginApiError.from(error, 'my-plugin.network');
      ctx.logger.error(apiError.code, apiError.message, apiError.details);
    }
  }
});

API 错误统一包成 PluginApiError，常见的 code 有 permission-denied、
invalid-argument、invalid-config、not-found、conflict、cancelled、
timeout、network-error、io-error 和 internal-error。判断错误类型靠
code，别靠错误文字。

完整权限分组如下：

分组权限
Playerplayer.start、player.control、player.observe、player.contribute
Filesfiles.dialog、files.read、files.write、files.watch
Windows / Appwindows.open、windows.manage、app.configure、app.quit
UI / Networkui.contribute、ui.notify、network.http、network.local
HTTP / Casthttp.routes、http.configure、cast.read、cast.share、cast.send、cast.configure
Time / Deep linkstime.read、time.synchronize、time.configure、deep-links.register、deep-links.dispatch
Logging / Pluginslogging.read、logging.configure、plugins.read、plugins.manage
Servicesservices.provide、services.consume
Commands / Eventscommands.register、commands.execute、events.publish、events.subscribe

有些权限是给以后能力预留的，当前 API 还没有对应的写操作。声明的时候只写你实际需
要的最小权限就行。

6. 开发约定

  • 所有宿主能力都从 ctx.api 走，别碰 Electron、window.api 或老 IPC。
  • command、event、service、RPC 协议统一放 shared contracts 文件里，用
    createPluginTokens() 生成强类型 token。
  • services.provide/use 只能同进程用；跨进程一律用 exposeRpc/rpc。RPC 的参数和返
    回值要求是可结构化克隆的数据。
  • UI 贡献只写在 renderer 入口；HTTP 路由和深链注册只写在 main 入口。
  • API 返回的会话或窗口句柄要留着，不用的时候调 close() 或 dispose()。
  • 配置先过 exams.parse/validate，或者交给 player.prepare/start* 的统一校验链
    路，别绕过校验直接驱动播放器。

开发的时候让 TypeScript 从 SDK 推断参数和返回类型就行。需要查完整字段的话，直接跳
到 SDK 里的 ExamAwareMainApi、ExamAwareRendererApi、PlayerStartOptions 和各领
域 *Api 接口定义。
