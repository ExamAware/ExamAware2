ExamAware 插件开发接口指南（API V2）

API V2 是插件访问 ExamAware 桌面能力的唯一推荐入口。插件应从
@dsz-examaware/plugin-sdk 导入类型和入口函数，并通过 ctx.api.<领域>.<方法>()
调用宿主能力；不要直接导入 Electron、访问 window.api，也不要自行发送字符串 IPC。

本文是快速开发指南。参数和返回值的最终定义以
contracts.ts 导出的 TypeScript 类型为准。

1. 最小插件

主进程入口适合文件、网络、后台服务、HTTP 路由等工作：

import { defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    const app = await ctx.api.app.info();
    ctx.logger.info(`Running on ExamAware ${app.version}`);
  }
});

渲染进程入口适合页面、菜单、编辑器面板和播放器工具栏等 UI 贡献：

import { defineRendererPlugin } from '@dsz-examaware/plugin-sdk';

export default defineRendererPlugin({
  activate(ctx) {
    return ctx.api.ui.home.register({
      id: 'open-editor',
      label: '打开编辑器',
      icon: 'edit',
      action: () => ctx.api.windows.openEditor()
    });
  }
});

在插件的 package.json 中声明 V2 入口、权限和渲染入口需要激活的窗口：

{
  "name": "@examaware-plugins/my-plugin",
  "version": "1.0.0",
  "examaware": {
    "apiVersion": 2,
    "targets": {
      "main": "./dist/main/index.cjs",
      "renderer": "./dist/renderer/index.mjs"
    },
    "permissions": ["player.start", "files.read", "ui.contribute", "windows.open"],
    "activation": {
      "rendererWindows": ["main", "editor", "player"]
    }
  }
}

rendererWindows 可选值为 main、editor、player、settings、cast、
logs、plugin-store、tray 和 plugin。省略时，V2 renderer 只在 main
窗口激活。没有 renderer 入口或 main 入口时，可以省略对应的 target。

2. 插件上下文

activate(ctx) 中常用的公共字段如下：

字段说明
ctx.api分类后的宿主 API，本文后续调用均从这里开始
ctx.plugin当前插件的名称、显示名、版本和 API 版本
ctx.process当前入口所在进程：main 或 renderer
ctx.logger自动带插件上下文的 debug/info/warn/error 日志器
ctx.permissionsgranted、has()、require() 权限查询接口
ctx.initialSettings激活时的只读初始设置
ctx.scope插件卸载时统一释放资源的作用域
ctx.window仅 renderer 存在，包含当前窗口的 id/kind/route

main 和 renderer 都有公共 API；只有 main 可以注册 HTTP 路由和深链处理器，
只有 renderer 有 ctx.api.ui。

3. API 总览

表中的“权限”是调用对应方法所需的 manifest 权限。- 表示无需额外声明。

app：应用信息和应用级操作

方法权限用途
info()-获取名称、版本、平台、是否为打包版本
getAutoStart()-读取开机自启动状态
setAutoStart(enabled)app.configure设置开机自启动
quit()app.quit退出 ExamAware
if (ctx.permissions.has('app.configure')) {
  await ctx.api.app.setAutoStart(true);
}

业务代码可通过 PluginPermissions.App.Configure 等常量检查权限，避免重复写权限
字符串；manifest 本身使用表中所列字符串。

player：准备、开始和控制放映

所有开始方式都会进入同一套解析、规范化、校验、窗口就绪确认和会话管理流程。

方法权限用途
prepare(source, options?)player.start只解析并校验来源，不打开窗口
start(source, options?)player.start使用统一的 PlayerSource 开始放映
startFromFile(path, options?)player.start + files.read从本地考试文件放映
startFromConfig(config, options?)player.start从已构造的 ExamConfig 放映
startFromJson(data, options?)player.start从 JSON 文本放映
startFromUrl(url, options?)player.start + network.http下载并放映远程配置
getSession(id)player.observe获取指定会话句柄
listSessions()player.observe获取所有会话快照
onSessionChanged(listener)player.observe订阅会话状态变化

start 和 prepare 接受四种来源：

type PlayerSource =
  | { kind: 'file'; path: string }
  | { kind: 'config'; config: ExamConfig }
  | { kind: 'json'; data: string }
  | { kind: 'url'; url: string; headers?: Readonly<Record<string, string>> };

URL 访问本机或私网时，还需 network.local 并显式设置
allowLocalNetwork: true。常用启动选项包括：

  • replaceExisting：替换已有放映，而不是另开会话。
  • waitForReady、readyTimeoutMs：等待窗口可用并设置等待超时。
  • requestTimeoutMs、maxBytes、allowLocalNetwork：限制远程来源请求。
  • validation：传入 ExamConfigValidationOptions 调整配置校验。
  • window.fullscreen/kiosk/alwaysOnTop/displayId：控制放映窗口。
const prepared = await ctx.api.player.prepare(
  { kind: 'url', url: 'https://example.com/exam.json' },
  { validation: { allowEmptyExamInfos: false } }
);

if (!prepared.validation.valid) {
  ctx.logger.warn('考试配置无效', prepared.validation.errors);
  return;
}

const session = await ctx.api.player.startFromConfig(prepared.config, {
  waitForReady: true,
  window: { fullscreen: true }
});
await session.focus();

PlayerSession 提供 snapshot()、focus()、close()、
replaceSource(source, options?) 和 dispose()。控制会话需要 player.control；
替换来源还需要 player.start 及该来源对应的文件或网络权限。

exams：考试配置处理

方法权限用途
parse(input)-解析 JSON 文本并返回完整校验结果
validate(input, options?)-校验任意输入，成功结果中包含类型化配置
normalize(config)-将合法配置规范为稳定结构
serialize(config, pretty?)-将配置序列化为 JSON
const result = ctx.api.exams.parse(json);
if (!result.valid || !result.config) {
  ctx.logger.warn('配置错误', result.errors);
  return;
}
const output = ctx.api.exams.serialize(ctx.api.exams.normalize(result.config), true);

files 和 dialogs：文件及系统对话框

API权限用途
files.open(options?)files.dialog选择文件或目录，返回路径数组
files.save(options?)files.dialog选择保存路径，取消时返回 undefined
files.readText(path) / readBytes(path)files.read读取文本或二进制内容
files.writeText(path, data) / writeBytes(path, data)files.write写入文本或二进制内容
files.exists(path) / stat(path)files.read查询存在性及类型、大小、修改时间
files.watch(path, listener)files.watch监听文件变化，返回 Disposable
dialogs.message(options)ui.notify显示系统消息框并取得所选按钮
dialogs.openFile(options?) / saveFile(options?)files.dialog文件对话框的语义化别名
const [path] = await ctx.api.dialogs.openFile({
  title: '选择考试配置',
  filters: [{ name: 'JSON', extensions: ['json'] }]
});
if (path) {
  const result = ctx.api.exams.parse(await ctx.api.files.readText(path));
  ctx.logger.info('配置校验结果', result.valid);
}

settings：当前插件设置

方法权限用途
get()-同步取得当前插件的只读设置
replace(settings)-替换全部设置
patch(partial)-浅合并部分设置
reset()-恢复插件默认设置
onChanged(listener)-监听设置变化

为 defineMainPlugin<MySettings>() 或 defineRendererPlugin<MySettings>() 提供设置类型后，
以上方法会得到完整 IDE 类型提示。

interface MySettings {
  enabled: boolean;
  endpoint?: string;
}

export default defineMainPlugin<MySettings>({
  activate(ctx) {
    ctx.scope.add(
      ctx.api.settings.onChanged((settings) => {
        ctx.logger.info('enabled changed', settings.enabled);
      })
    );
  }
});

windows：窗口导航和插件窗口

方法权限用途
open(options?)windows.open创建插件窗口并返回句柄
get(id)windows.manage按插件窗口 ID 获取句柄
openMain()windows.open打开主界面
openEditor(path?)windows.open打开编辑器，可直接载入文件
openSettings(page?)windows.open打开设置，可指定页面
openCast() / openLogs() / openPluginStore()windows.open打开投送、日志或插件商店

插件窗口句柄提供 focus()、close() 和 dispose()，这些操作需要
windows.manage。

const window = await ctx.api.windows.open({
  id: 'preview',
  route: '/preview',
  title: '预览',
  width: 900,
  height: 640
});
ctx.scope.add(window);

commands 和 events：类型化命令与事件

方法权限用途
commands.register(token, handler, options?)commands.register注册命令，返回 Disposable
commands.execute(token, args)commands.execute执行命令并取得类型化结果
commands.has(token)-查询当前进程中是否已有命令
events.on(token, listener) / once(...)events.subscribe持续或单次订阅事件
events.emit(token, payload)events.publish发布类型化事件

token 应集中定义在 main 和 renderer 都能导入的 shared/contracts.ts 中：

import { createPluginTokens } from '@dsz-examaware/plugin-sdk';

const tokens = createPluginTokens('@examaware-plugins/my-plugin');

export const refreshCommand = tokens.command<{ force: boolean }, number>('refresh');
export const configChanged = tokens.event<{ revision: number }>('config-changed');
ctx.scope.add(
  ctx.api.commands.register(refreshCommand, async ({ force }) => (force ? 1 : 0), {
    title: '刷新插件数据'
  })
);
const revision = await ctx.api.commands.execute(refreshCommand, { force: true });
ctx.api.events.emit(configChanged, { revision });

不要把 command ID、event ID 或参数类型散落成裸字符串。

notifications：应用内通知

方法权限用途
show(options)ui.notify显示 info/success/warning/error 通知，可设置持续时间
await ctx.api.notifications.show({
  level: 'success',
  title: '导入完成',
  message: '考试配置已通过校验'
});

time：统一时钟和时间同步

方法权限用途
now()time.read获取经过同步偏移修正的当前时间戳
info()time.read获取偏移量、服务器和同步状态
synchronize()time.synchronize立即执行时间同步
configure(config)time.configure更新同步配置并返回规范化结果
onChanged(listener)time.read监听同步状态变化

需要与放映时钟一致时使用 await ctx.api.time.now()，不要自行拼接内部时间 IPC。

cast：局域网投送

方法权限用途
peers()cast.read列出发现的设备
localShares()cast.read列出本机共享的考试
peerShares(peerId)cast.read列出指定设备的共享
getPeerConfig(peerId, shareId?)cast.read读取对端共享配置 JSON
send(peerId, source)cast.send将文件、配置、JSON 或 URL 来源发送给设备
const [peer] = await ctx.api.cast.peers();
if (peer) {
  await ctx.api.cast.send(peer.id, { kind: 'config', config });
}

network：受控网络请求

方法权限用途
request(url, options?)network.http发起请求并取得状态、响应头和二进制正文
getText(url, options?)network.http获取文本
getJson<T>(url, options?)network.http获取并解析类型化 JSON

请求选项支持 method、headers、body、timeoutMs、maxBytes 和
allowLocalNetwork。访问本机或私网还需 network.local。request() 的响应提供
status、headers、body、text() 和 json<T>()。

interface RemoteStatus {
  online: boolean;
}

const status = await ctx.api.network.getJson<RemoteStatus>('https://example.com/status', {
  timeoutMs: 5_000,
  maxBytes: 64 * 1024
});

http：ExamAware 内置 HTTP 服务

方法进程权限用途
baseUrl()main/renderer-获取当前服务基址
configure(config)main/rendererhttp.configure更新服务配置
restart()main/rendererhttp.configure重启服务
registerRoute(route)仅 mainhttp.routes注册插件路由，返回 Disposable
ctx.scope.add(
  ctx.api.http.registerRoute({
    method: 'GET',
    path: '/plugins/my-plugin/status',
    summary: '插件状态',
    requireAuth: true,
    handler: ({ query }) => ({
      status: 200,
      body: { ok: true, detail: query.detail === '1' }
    })
  })
);

路由处理器接收 method/path/query/headers/body，返回可选的
status/headers/body。路由注册只能写在 main 入口。

deepLinks：深链

方法进程权限用途
dispatch(url)main/rendererdeep-links.dispatch主动分派一个深链 URL
onOpened(listener)main/rendererevents.subscribe监听宿主收到的深链
register(path, handler)仅 maindeep-links.register注册路径处理器，返回 Disposable
ctx.scope.add(
  ctx.api.deepLinks.register('/my-plugin/open', async ({ query }) => {
    ctx.logger.info('Opening item', query.id);
    return true;
  })
);

payload 包含 raw/scheme/host/pathname/query。处理器返回 true 表示已处理。

logging：结构化日志

方法权限用途
createLogger(scope)-创建带子作用域的日志器
entries()logging.read读取日志条目

一般直接使用 ctx.logger；复杂插件可用
ctx.api.logging.createLogger('sync') 分出稳定的日志领域。

plugins：插件状态和管理

方法权限用途
current()-同步取得当前插件信息
list()plugins.read列出插件及状态
enable(name) / disable(name) / reload(name)plugins.manage管理指定插件

插件信息包含名称、显示名、版本、状态、启用状态和 API 版本。

const installedPlugins = await ctx.api.plugins.list();

services：同进程服务和跨进程 RPC

方法权限用途
provide(token, service)services.provide在当前进程提供对象服务，返回 Disposable
use(token)services.consume在当前进程取得对象服务
has(token)-查询当前进程是否存在服务
exposeRpc(token, service)services.provide暴露可跨 main/renderer 调用的 RPC 服务
rpc(token)services.consume创建强类型 RPC 客户端代理

同进程服务可以包含函数，但不能直接跨 Electron 进程传递。跨 main/renderer
必须定义 RPC token：

// shared/contracts.ts
import { createPluginTokens } from '@dsz-examaware/plugin-sdk';

const tokens = createPluginTokens('@examaware-plugins/my-plugin');

export interface DataService {
  load(id: string): Promise<{ value: string }>;
}

export const dataService = tokens.rpc<DataService>('data-service');
// main
ctx.api.services.exposeRpc(dataService, {
  async load(id) {
    return { value: `item:${id}` };
  }
});

// renderer：方法名、参数和返回值均由 IDE 校验
const data = await ctx.api.services.rpc(dataService).load('42');

createPluginTokens(namespace) 还提供 .service<T>()、.command<A, R>()、
.event<T>() 和 .apiModule<T>()。普通插件通常不需要自定义宿主 API module。

ui：界面贡献（仅 renderer）

home/pages/settings/editor/menus 的注册需要 ui.contribute；播放器工具栏注册只需要
player.contribute。ui.editor.clearView() 无需额外权限。

方法用途
ui.home.register(item)注册主页操作入口
ui.pages.register(page)注册插件页面和路由
ui.settings.registerPage(page)注册设置页面
ui.editor.registerPanel(panel)注册编辑器面板
ui.editor.presentView(view)临时呈现编辑器视图
ui.editor.clearView(id?)清除一个或全部临时编辑器视图
ui.player.registerToolbarItem(item)注册播放器工具栏动作
ui.menus.register(item)将类型化 command 注册为菜单项

组件可直接传框架组件，也可传返回组件的异步工厂：

await ctx.api.ui.settings.registerPage({
  id: 'general',
  label: '我的插件',
  icon: 'extension',
  order: 50,
  component: () => import('./MySettingsPage.vue')
});

home/pages/settings/editor/player/menus 分别只在对应宿主表面有意义；用
activation.rendererWindows 精确声明需要加载 renderer 的窗口，避免无关窗口加载插件。

4. 生命周期和资源清理

V2 支持以下生命周期：

  1. onLoad(ctx)：激活前准备。
  2. activate(ctx)：注册能力和启动插件；必需。
  3. onReady(ctx)：激活成功后执行。
  4. deactivate(ctx)：卸载前停止业务。
  5. 释放 activate 返回的函数或 Disposable，并释放 ctx.scope。
  6. onUnload(ctx)：最终清理。
  7. onError(error, ctx)：生命周期失败时接收统一的 PluginApiError。

注册命令、事件、路由、UI 项等 API 返回 Disposable，宿主也会将注册项归入
当前插件作用域。对插件自己创建的定时器、观察器或外部资源，应显式加入 scope：

export default defineMainPlugin({
  activate(ctx) {
    const timer = setInterval(() => ctx.logger.debug('tick'), 10_000);
    ctx.scope.defer(() => clearInterval(timer));

    ctx.scope.add(
      ctx.api.events.on(configChanged, ({ revision }) => {
        ctx.logger.info('revision', revision);
      })
    );
  }
});

ctx.scope.add(disposable) 接受 Disposable 或清理函数；
ctx.scope.defer(fn) 用于把任意清理函数包装进作用域。重复释放是安全的。

5. 权限和错误处理

默认授予 time.read、logging.read、plugins.read 和 events.subscribe；其他权限
必须列入 examaware.permissions。推荐用常量做运行时能力分支：

import { PluginApiError, PluginPermissions, defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    if (!ctx.permissions.has(PluginPermissions.Network.Http)) return;

    try {
      await ctx.api.network.getText('https://example.com/ping');
    } catch (error) {
      const apiError = PluginApiError.from(error, 'my-plugin.network');
      ctx.logger.error(apiError.code, apiError.message, apiError.details);
    }
  }
});

API 错误统一为 PluginApiError，常见 code 包括 permission-denied、
invalid-argument、invalid-config、not-found、conflict、cancelled、
timeout、network-error、io-error 和 internal-error。不要依赖错误消息文本判断类型。

完整权限分组为：

分组权限
Playerplayer.start、player.control、player.observe、player.contribute
Filesfiles.dialog、files.read、files.write、files.watch
Windows / Appwindows.open、windows.manage、app.configure、app.quit
UI / Networkui.contribute、ui.notify、network.http、network.local
HTTP / Casthttp.routes、http.configure、cast.read、cast.share、cast.send、cast.configure
Time / Deep linkstime.read、time.synchronize、time.configure、deep-links.register、deep-links.dispatch
Logging / Pluginslogging.read、logging.configure、plugins.read、plugins.manage
Servicesservices.provide、services.consume
Commands / Eventscommands.register、commands.execute、events.publish、events.subscribe

部分权限为后续能力预留，当前 API 没有对应写操作；只声明实际需要的最小权限。

6. 开发约定

  • 所有宿主能力均从 ctx.api 访问；不要使用 Electron、window.api 或旧 IPC。
  • command、event、service 和 RPC 协议集中放在 shared contracts 文件，使用
    createPluginTokens() 生成强类型 token。
  • services.provide/use 仅用于同进程；跨进程一律使用 exposeRpc/rpc，RPC 参数和
    返回值应为可结构化克隆的数据。
  • UI 贡献只写在 renderer 入口；HTTP 路由和深链注册只写在 main 入口。
  • 保留 API 返回的会话或窗口句柄；不再使用时调用 close() 或 dispose()。
  • 配置先通过 exams.parse/validate，或交给 player.prepare/start* 的统一校验链路，
    不要绕过校验直接驱动播放器。

开发时让 TypeScript 从 SDK 推断参数和返回类型即可。需要查询完整字段时，优先跳转到
SDK 的 ExamAwareMainApi、ExamAwareRendererApi、PlayerStartOptions 和各领域
*Api 接口定义。
