# ExamAware 插件开发指南（API V2）

API V2 是插件与 ExamAware 桌面端交互的统一接口。插件入口和类型从
`@dsz-examaware/plugin-sdk` 导入，宿主能力通过 `ctx.api.<领域>.<方法>()` 调用。
不要在插件中直接导入 Electron、访问 `window.api`，也不要自行拼接 IPC 通道。

本文用于快速上手。完整参数和返回值以
[`contracts.ts`](../packages/plugin-sdk/src/api/contracts.ts) 中的 TypeScript 定义为准。

## 1. 写一个最小的插件

Main 进程入口适合搞文件操作、网络请求、后台服务、HTTP 路由这些东西：

```ts
import { defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    const app = await ctx.api.app.info();
    ctx.logger.info(`跑在 ExamAware ${app.version} 上`);
  }
});
```

Renderer 进程入口适合搞页面、菜单、编辑器面板、播放器工具栏这些 UI 类的活：

```ts
import { defineRendererPlugin } from '@dsz-examaware/plugin-sdk';

export default defineRendererPlugin({
  activate(ctx) {
    return ctx.api.ui.home.register({
      id: 'open-editor',
      label: '打开编辑器',
      icon: 'edit',
      action: () => ctx.api.windows.openEditor()
    });
  }
});
```

然后在插件的 `package.json` 里声明 V2 入口、权限、以及 renderer 需要在哪些窗口激
活：

```json
{
  "name": "@examaware-plugins/my-plugin",
  "version": "1.0.0",
  "examaware": {
    "apiVersion": 2,
    "targets": {
      "main": "./dist/main/index.cjs",
      "renderer": "./dist/renderer/index.mjs"
    },
    "permissions": ["control.replace", "network.websocket", "ui.contribute"],
    "activation": {
      "rendererWindows": ["main", "player", "control-bind"]
    }
  }
}
```

`rendererWindows` 可以写 `main`、`editor`、`player`、`settings`、`cast`、
`logs`、`plugin-store`、`control-bind`、`tray`、`plugin`。不写时，V2 renderer 默认
只在 `main` 窗口激活。自定义集控绑定界面需要包含 `control-bind`。

`activate(ctx)` 里你能拿到这些东西：

| 字段                  | 干嘛用的                                       |
| --------------------- | ---------------------------------------------- |
| `ctx.api`             | 所有宿主 API 的入口，后面的调用都从它开始      |
| `ctx.plugin`          | 当前插件的名称、显示名、版本、API 版本         |
| `ctx.process`         | 当前入口跑在哪个进程：`main` 还是 `renderer`   |
| `ctx.logger`          | 自带插件前缀的 `debug/info/warn/error` 日志器  |
| `ctx.permissions`     | `granted`、`has()`、`require()` 查权限用       |
| `ctx.initialSettings` | 激活那一刻的初始设置快照，只读                 |
| `ctx.scope`           | 统一管理资源释放的作用域，插件卸载时自动清理   |
| `ctx.window`          | 只有 renderer 里有，当前窗口的 `id/kind/route` |

main 和 renderer 都有公共 API。只有 main 能注册 HTTP 路由和深链处理器，只有
renderer 能用到 `ctx.api.ui`。

## 3. API 速览

表格里的"权限"就是 manifest 里要写的东西。`-` 意思是这个不用额外声明。

### `app`：应用信息和全局操作

| 方法                    | 权限            | 用途                             |
| ----------------------- | --------------- | -------------------------------- |
| `info()`                | -               | 拿到名称、版本、平台、是否打包版 |
| `getAutoStart()`        | -               | 看开机自启有没有开               |
| `setAutoStart(enabled)` | `app.configure` | 开关开机自启                     |
| `quit()`                | `app.quit`      | 退出 ExamAware                   |

```ts
if (ctx.permissions.has('app.configure')) {
  await ctx.api.app.setAutoStart(true);
}
```

写代码的时候建议用 `PluginPermissions.App.Configure` 这种常量来查权限，不用手写字
符串。manifest 里还是用表里列的那些字符串。

### `player`：准备、开始、控制放映

不管你用哪种方式开始放映，最终都会进同一套流程：解析 → 规范化 → 校验 → 确认窗口准
备好 → 会话管理。

| 方法                                | 权限                            | 用途                             |
| ----------------------------------- | ------------------------------- | -------------------------------- |
| `prepare(source, options?)`         | `player.start`                  | 只解析校验，不弹窗口             |
| `start(source, options?)`           | `player.start`                  | 走统一的 `PlayerSource` 开始放映 |
| `startFromFile(path, options?)`     | `player.start` + `files.read`   | 从本地考试文件开始放             |
| `startFromConfig(config, options?)` | `player.start`                  | 从已经拼好的 `ExamConfig` 开始放 |
| `startFromJson(data, options?)`     | `player.start`                  | 从一段 JSON 文本开始放           |
| `startFromUrl(url, options?)`       | `player.start` + `network.http` | 下载远程配置然后放               |
| `getSession(id)`                    | `player.observe`                | 拿到指定会话的句柄               |
| `listSessions()`                    | `player.observe`                | 拿到所有会话的快照               |
| `onSessionChanged(listener)`        | `player.observe`                | 订阅会话状态变化                 |

`start` 和 `prepare` 接受四种来源：

```ts
type PlayerSource =
  | { kind: 'file'; path: string }
  | { kind: 'config'; config: ExamConfig }
  | { kind: 'json'; data: string }
  | { kind: 'url'; url: string; headers?: Readonly<Record<string, string>> };
```

URL 指向本机或者局域网的时候，还要 `network.local` 权限，并且要传
`allowLocalNetwork: true`。常用的启动选项有这些：

- `replaceExisting`：替换已有的放映，不新开会话。
- `waitForReady`、`readyTimeoutMs`：等窗口准备好，可以设超时。
- `requestTimeoutMs`、`maxBytes`、`allowLocalNetwork`：限制远程请求。
- `validation`：传 `ExamConfigValidationOptions` 来调校验行为。
- `window.fullscreen/kiosk/alwaysOnTop/displayId`：控制放映窗口的行为。

```ts
const prepared = await ctx.api.player.prepare(
  { kind: 'url', url: 'https://example.com/exam.json' },
  { validation: { allowEmptyExamInfos: false } }
);

if (!prepared.validation.valid) {
  ctx.logger.warn('考试配置有问题', prepared.validation.errors);
  return;
}

const session = await ctx.api.player.startFromConfig(prepared.config, {
  waitForReady: true,
  window: { fullscreen: true }
});
await session.focus();
```

`PlayerSession` 有 `snapshot()`、`focus()`、`close()`、`replaceSource(source, options?)`
和 `dispose()` 这些方法。控制会话要 `player.control` 权限；替换来源还要
`player.start` 加上对应的文件或网络权限。

### `exams`：处理考试配置

| 方法                         | 权限 | 用途                             |
| ---------------------------- | ---- | -------------------------------- |
| `parse(input)`               | -    | 解析 JSON 文本，返回完整校验结果 |
| `validate(input, options?)`  | -    | 校验输入，成功的话给你类型化配置 |
| `normalize(config)`          | -    | 把合法配置整理成稳定结构         |
| `serialize(config, pretty?)` | -    | 把配置转回 JSON 字符串           |

```ts
const result = ctx.api.exams.parse(json);
if (!result.valid || !result.config) {
  ctx.logger.warn('配置不对', result.errors);
  return;
}
const output = ctx.api.exams.serialize(ctx.api.exams.normalize(result.config), true);
```

### `files` 和 `dialogs`：文件和系统对话框

| API                                                      | 权限           | 用途                                 |
| -------------------------------------------------------- | -------------- | ------------------------------------ |
| `files.open(options?)`                                   | `files.dialog` | 选文件或目录，返回路径数组           |
| `files.save(options?)`                                   | `files.dialog` | 选保存路径，取消的话返回 `undefined` |
| `files.readText(path)` / `readBytes(path)`               | `files.read`   | 读文本或二进制                       |
| `files.writeText(path, data)` / `writeBytes(path, data)` | `files.write`  | 写文本或二进制                       |
| `files.exists(path)` / `stat(path)`                      | `files.read`   | 看看文件在不在，以及类型大小时间     |
| `files.watch(path, listener)`                            | `files.watch`  | 监听文件变化，返回 `Disposable`      |
| `dialogs.message(options)`                               | `ui.notify`    | 弹出系统消息框，拿到用户点了哪个     |
| `dialogs.openFile(options?)` / `saveFile(options?)`      | `files.dialog` | 就是文件对话框，语义别名             |

```ts
const [path] = await ctx.api.dialogs.openFile({
  title: '选一个考试配置',
  filters: [{ name: 'JSON', extensions: ['json'] }]
});
if (path) {
  const result = ctx.api.exams.parse(await ctx.api.files.readText(path));
  ctx.logger.info('配置校验结果', result.valid);
}
```

### `settings`：当前插件的设置

| 方法                  | 权限 | 用途                 |
| --------------------- | ---- | -------------------- |
| `get()`               | -    | 同步拿当前设置，只读 |
| `replace(settings)`   | -    | 整个替换             |
| `patch(partial)`      | -    | 浅合并一部分字段     |
| `reset()`             | -    | 恢复默认设置         |
| `onChanged(listener)` | -    | 监听设置变化         |

给 `defineMainPlugin<MySettings>()` 或 `defineRendererPlugin<MySettings>()`
传个类型参数，所有方法都会在 IDE 里有自动补全。

```ts
interface MySettings {
  enabled: boolean;
  endpoint?: string;
}

export default defineMainPlugin<MySettings>({
  activate(ctx) {
    ctx.scope.add(
      ctx.api.settings.onChanged((settings) => {
        ctx.logger.info('enabled 变了', settings.enabled);
      })
    );
  }
});
```

### `appSettings`：应用全局设置

`ctx.api.settings` 只管理当前插件自己的配置。需要读取或修改 ExamAware 全局设置时，
使用 `ctx.api.appSettings`：

| 方法                           | 权限                 | 用途                   |
| ------------------------------ | -------------------- | ---------------------- |
| `all()` / `get(key, default?)` | `app.settings.read`  | 读取全部设置或指定路径 |
| `set(key, value)`              | `app.settings.write` | 修改指定路径           |
| `patch(settings)`              | `app.settings.write` | 合并一组设置           |
| `onChanged(listener)`          | `app.settings.read`  | 监听全局设置变化       |

由集控策略锁定的设置不能通过 `set()` 或 `patch()` 修改。集控插件应通过
`control.applyManagedSettings()` 下发并锁定这些值。

```ts
const theme = await ctx.api.appSettings.get('appearance.theme', 'auto');
await ctx.api.appSettings.patch({
  appearance: { theme: 'dark' },
  player: { uiScale: 1.1 }
});
```

### `control`：内置集控与自定义集控提供者

普通插件可以读取集控状态。需要接入自有集控系统的插件，应在 main 入口声明
`control.replace` 并注册一个提供者。注册后，应用中的状态展示、绑定、解绑和呼叫巡考
都会转发给该提供者；释放返回的 `Disposable` 后自动恢复内置集控。

| 方法                                      | 进程          | 权限              | 用途                   |
| ----------------------------------------- | ------------- | ----------------- | ---------------------- |
| `getStatus()` / `onStatusChanged()`       | main/renderer | `control.read`    | 读取和监听当前集控状态 |
| `bind()` / `unbind()` / `callProctor()`   | main/renderer | `control.manage`  | 操作当前集控提供者     |
| `registerProvider(provider)`              | 仅 main       | `control.replace` | 用插件接管集控入口     |
| `useBuiltinProvider()`                    | 仅 main       | `control.replace` | 主动恢复内置集控       |
| `applyManagedSettings(settings, options)` | 仅 main       | `control.policy`  | 写入并锁定应用设置     |
| `clearManagedSettings(keys?)`             | 仅 main       | `control.policy`  | 解除指定或全部设置锁定 |

```ts
export default defineMainPlugin({
  activate(ctx) {
    let status: Omit<ControlStatusSnapshot, 'provider' | 'providerPlugin'> = {
      state: 'unenrolled',
      managedSettingKeys: []
    };
    const listeners = new Set<(status: typeof status) => void>();
    const updateStatus = (next: typeof status) => {
      status = next;
      listeners.forEach((listener) => listener(status));
    };

    ctx.api.control.registerProvider({
      getStatus: () => status,
      onStatusChanged(listener) {
        listeners.add(listener);
        return () => listeners.delete(listener);
      },
      async bind(input) {
        const registration = await myControlClient.enroll(input);
        updateStatus({
          state: 'online',
          deviceId: registration.deviceId,
          serverUrl: registration.serverUrl,
          managedSettingKeys: []
        });
        return status;
      },
      async unbind() {
        await myControlClient.unbind();
        updateStatus({ state: 'unenrolled', managedSettingKeys: [] });
        return status;
      },
      callProctor: (input) => myControlClient.callProctor(input)
    });
  }
});
```

提供者状态不需要填写 `provider` 和 `providerPlugin`，宿主会自动补全。外部状态变化通过
`onStatusChanged(listener)` 推送；`bind()`、`unbind()` 返回后，宿主也会读取并广播最新状态。

`applyManagedSettings()` 的键与桌面设置路径一致，例如 `appearance.theme`、
`player.uiScale`。时间同步键可使用协议形式 `timeSync.autoSync`。`replace: true` 会先解除
已有策略再写入本次策略；`clearManagedSettings()` 只解除锁定，不改写当前设置值。

自定义集控的绑定流程通常与内置向导不同。renderer 入口可以注册完整的绑定页面：

```ts
export default defineRendererPlugin({
  activate(ctx) {
    ctx.api.ui.control.registerBindingView({
      id: 'school-control-binding',
      component: () => import('./ControlBindingView.vue')
    });
  }
});
```

打开“绑定集控”窗口时，宿主优先显示插件注册的组件。组件可以通过插件 RPC 调用 main
入口中的自有客户端，不需要使用内置服务器地址或绑定码表单。插件卸载或释放注册句柄后，
窗口恢复内置绑定向导。

### `windows`：窗口导航和插件窗口

| 方法                                              | 权限             | 用途                         |
| ------------------------------------------------- | ---------------- | ---------------------------- |
| `open(options?)`                                  | `windows.open`   | 创建插件窗口，返回句柄       |
| `get(id)`                                         | `windows.manage` | 按插件窗口 ID 拿到句柄       |
| `openMain()`                                      | `windows.open`   | 打开主界面                   |
| `openEditor(path?)`                               | `windows.open`   | 打开编辑器，可以直接载入文件 |
| `openSettings(page?)`                             | `windows.open`   | 打开设置，可以指定页面       |
| `openCast()` / `openLogs()` / `openPluginStore()` | `windows.open`   | 打开投送、日志、插件商店     |

插件窗口句柄有 `focus()`、`close()` 和 `dispose()`，操作句柄要 `windows.manage` 权限。

```ts
const window = await ctx.api.windows.open({
  id: 'preview',
  route: '/preview',
  title: '预览',
  width: 900,
  height: 640
});
ctx.scope.add(window);
```

### `commands` 和 `events`：类型化命令与事件

| 方法                                          | 权限                | 用途                        |
| --------------------------------------------- | ------------------- | --------------------------- |
| `commands.register(token, handler, options?)` | `commands.register` | 注册命令，返回 `Disposable` |
| `commands.execute(token, args)`               | `commands.execute`  | 执行命令                    |
| `commands.has(token)`                         | -                   | 查询命令是否存在            |
| `events.on(token, listener)` / `once(...)`    | `events.subscribe`  | 订阅事件                    |
| `events.emit(token, payload)`                 | `events.publish`    | 发布事件                    |

命令、事件和 RPC token 放在 main 与 renderer 都能导入的 shared 文件中，并通过
`createPluginTokens()` 创建。

### `network`：HTTP 客户端和套接字

HTTP API 在 main 和 renderer 中都可用，支持 `baseUrl`、查询参数、JSON 请求体、默认请求
配置、超时、响应大小限制和局域网访问控制。

| 方法                                | 权限                | 用途                         |
| ----------------------------------- | ------------------- | ---------------------------- |
| `request/get/post/put/patch/delete` | `network.http`      | 发送 HTTP/HTTPS 请求         |
| `getText()` / `getJson<T>()`        | `network.http`      | 直接读取文本或 JSON          |
| `createClient(defaults)`            | `network.http`      | 创建带默认配置的 HTTP 客户端 |
| `connectWebSocket()`                | `network.websocket` | 建立 WS/WSS 长连接           |
| `connectTcp()`                      | `network.tcp`       | 建立 TCP 或 TLS 连接         |
| `createUdpSocket()`                 | `network.udp`       | 创建 UDP 套接字              |

访问本机或内网地址时还要声明 `network.local` 并设置 `allowLocalNetwork: true`。UDP
绑定本地地址或端口时还要 `network.listen`。WebSocket、TCP、UDP 只在 main 入口提供；
renderer 需要使用时，应通过插件 RPC 暴露业务方法。

```ts
const client = ctx.api.network.createClient({
  baseUrl: 'https://control.example.edu/api/',
  timeoutMs: 10_000,
  headers: { authorization: `Bearer ${token}` }
});

const response = await client.post('devices/heartbeat', { status: 'online' });
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const payload = response.json<{ accepted: boolean }>();

const ws = await ctx.api.network.connectWebSocket('wss://control.example.edu/device');
ws.onMessage((message) => ctx.logger.info('收到集控消息', message));
await ws.send(JSON.stringify({ type: 'hello' }));
```

TCP 支持 `tls/serverName`，UDP 支持 `udp4/udp6` 和可选本地绑定。套接字句柄归插件作用域
管理，插件停用时会自动关闭，也可以主动调用 `close()`、`end()` 或 `dispose()`。

```ts
await ctx.api.notifications.show({
```

### `time`：统一时钟和时间同步

| 方法                  | 权限               | 用途                           |
| --------------------- | ------------------ | ------------------------------ |
| `now()`               | `time.read`        | 拿经过同步偏移修正的当前时间戳 |
| `info()`              | `time.read`        | 拿偏移量、服务器、同步状态     |
| `synchronize()`       | `time.synchronize` | 立刻执行时间同步               |
| `configure(config)`   | `time.configure`   | 更新同步配置，返回规范化结果   |
| `onChanged(listener)` | `time.read`        | 监听同步状态变化               |

### `cast`：局域网投送

```ts
const [peer] = await ctx.api.cast.peers();

}
```

### `http`：ExamAware 内置 HTTP 服务

| 方法                   | 进程          | 权限             | 用途                            |
| ---------------------- | ------------- | ---------------- | ------------------------------- |
| `baseUrl()`            | main/renderer | -                | 拿到当前服务的基址              |
| `configure(config)`    | main/renderer | `http.configure` | 更新服务配置                    |
| `restart()`            | main/renderer | `http.configure` | 重启服务                        |
| `registerRoute(route)` | 仅 main       | `http.routes`    | 注册插件路由，返回 `Disposable` |

```ts
ctx.scope.add(
  ctx.api.http.registerRoute({
    method: 'GET',
    path: '/plugins/my-plugin/status',
    summary: '插件状态',
    requireAuth: true,
    handler: ({ query }) => ({
      status: 200,
      body: { ok: true, detail: query.detail === '1' }
    })
  })
);
```

路由处理函数能拿到 `method/path/query/headers/body`，返回 `status/headers/body`，
都可以不写。路由注册只能写在 main 入口。

### `deepLinks`：深链

| 方法                          | 进程          | 权限                  | 用途                                 |
| ----------------------------- | ------------- | --------------------- | ------------------------------------ |
| `dispatch(url)`               | main/renderer | `deep-links.dispatch` | 主动分派一个深链 URL                 |
| `onOpened(listener)`          | main/renderer | `events.subscribe`    | 监听宿主收到的深链                   |
| `register(route, handler)`    | 仅 main       | `deep-links.register` | 注册 host/path 路由，返回 Disposable |
| `registerHost(host, handler)` | 仅 main       | `deep-links.register` | 注册 host 下的所有路径               |
| `use(middleware)`             | 仅 main       | `deep-links.register` | 注册洋葱模型 middleware              |

```ts
ctx.scope.add(
  ctx.api.deepLinks.register({ host: 'my-plugin', path: '/open' }, async ({ query }) => {
    ctx.logger.info('打开项', query.id);
    return true;
  })
);

ctx.scope.add(
  ctx.api.deepLinks.use(async (context, next) => {
    ctx.logger.debug('deeplink before', context.payload.raw);
    await next();
    ctx.logger.debug('deeplink handled', context.handled);
  })
);
```

`register('/my-plugin/open', handler)` 仍然有效，并映射到同一条 host/path 路由。字符串、
`RegExp` 和 `(payload) => boolean` 都可作为 `path` 匹配器。payload 保持
`raw/scheme/host/pathname/search/query`；handler 返回 `true` 表示已处理。

### `logging`：结构化日志

| 方法                  | 权限           | 用途                   |
| --------------------- | -------------- | ---------------------- |
| `createLogger(scope)` | -              | 创建带子作用域的日志器 |
| `entries()`           | `logging.read` | 读取日志条目           |

一般情况下直接用 `ctx.logger` 就够了。复杂插件可以用
`ctx.api.logging.createLogger('sync')` 分出独立的日志 channel。

### `plugins`：插件状态和管理

| 方法                                                  | 权限              | 用途                 |
| ----------------------------------------------------- | ----------------- | -------------------- |
| `current()`                                           | -                 | 读取当前插件信息     |
| `list()`                                              | `plugins.read`    | 列出所有插件和状态   |
| `enable()` / `disable()` / `reload()` / `uninstall()` | `plugins.manage`  | 管理其他插件         |
| `installFromDirectory()` / `installPackage()`         | `plugins.install` | 安装普通权限插件     |
| `installFromRegistry()`                               | `plugins.install` | 从注册表安装普通插件 |

插件 API 不允许静默安装请求高权限的插件。此类插件必须经过应用安装页面的权限确认弹窗。

### `services`：同进程服务和跨进程 RPC

| 方法                        | 权限               | 用途                                      |
| --------------------------- | ------------------ | ----------------------------------------- |
| `provide(token, service)`   | `services.provide` | 在当前进程提供对象服务，返回 `Disposable` |
| `use(token)`                | `services.consume` | 在当前进程拿到服务对象                    |
| `has(token)`                | -                  | 查当前进程有没有这个服务                  |
| `exposeRpc(token, service)` | `services.provide` | 暴露跨 main/renderer 调用的 RPC 服务      |
| `rpc(token)`                | `services.consume` | 创建类型安全的 RPC 客户端代理             |

同进程服务可以包含函数，但不能直接跨 Electron 进程传递。跨 main/renderer 必须定
义 RPC token：

```ts
// shared/contracts.ts
import { createPluginTokens } from '@dsz-examaware/plugin-sdk';

const tokens = createPluginTokens('@examaware-plugins/my-plugin');

export interface DataService {
  load(id: string): Promise<{ value: string }>;
}

export const dataService = tokens.rpc<DataService>('data-service');
```

```ts
// main
ctx.api.services.exposeRpc(dataService, {
  async load(id) {
    return { value: `item:${id}` };
  }
});

// renderer：方法名、参数、返回值 IDE 全帮你检查
const data = await ctx.api.services.rpc(dataService).load('42');
```

`createPluginTokens(namespace)` 还能生成 `.service<T>()`、`.command<A, R>()`、
`.event<T>()` 和 `.apiModule<T>()`。普通插件一般不需要自定义宿主 API module。

### `ui`：界面贡献（仅 renderer）

`home/pages/settings/editor/menus` 的注册要 `ui.contribute` 权限；播放器工具栏注册只
要 `player.contribute`。`ui.editor.clearView()` 不用额外权限。

| 方法                                  | 用途                          |
| ------------------------------------- | ----------------------------- |
| `ui.home.register(item)`              | 注册主页操作入口              |
| `ui.pages.register(page)`             | 注册插件页面和路由            |
| `ui.settings.registerPage(page)`      | 注册设置页面                  |
| `ui.editor.registerPanel(panel)`      | 注册编辑器面板                |
| `ui.editor.presentView(view)`         | 临时呈现一个编辑器视图        |
| `ui.editor.clearView(id?)`            | 清除一个或全部临时视图        |
| `ui.player.registerToolbarItem(item)` | 注册播放器工具栏按钮          |
| `ui.menus.register(item)`             | 把类型化 command 注册为菜单项 |

组件可以直接传框架组件，也可以传返回组件的异步工厂函数：

```ts
await ctx.api.ui.settings.registerPage({
  id: 'general',
  label: '我的插件',
  icon: 'extension',
  order: 50,
  component: () => import('./MySettingsPage.vue')
});
```

`home/pages/settings/editor/player/menus` 分别在对应的宿主界面上才有意义。用
`activation.rendererWindows` 精确声明哪些窗口要加载 renderer，别让插件在不相关
的窗口里白跑。

## 4. 生命周期和资源清理

V2 的生命周期一共这些步骤：

1. `onLoad(ctx)`：激活前准备。
2. `activate(ctx)`：注册能力、启动插件。这个是必须的。
3. `onReady(ctx)`：激活成功之后跑。
4. `deactivate(ctx)`：卸载前停业务。
5. 释放 `activate` 返回的函数或 `Disposable`，同时清空 `ctx.scope`。
6. `onUnload(ctx)`：最终清理。
7. `onError(error, ctx)`：生命周期出问题的时候收一个统一的 `PluginApiError`。

注册命令、事件、路由、UI 项这些 API 返回的都是 `Disposable`，宿主会自动把这些注
册项归到当前插件的作用域里。但你自己创建的定时器、观察器之类的，记得显式加到 scope：

```ts
export default defineMainPlugin({
  activate(ctx) {
    const timer = setInterval(() => ctx.logger.debug('滴'), 10_000);
    ctx.scope.defer(() => clearInterval(timer));

    ctx.scope.add(
      ctx.api.events.on(configChanged, ({ revision }) => {
        ctx.logger.info('revision', revision);
      })
    );
  }
});
```

`ctx.scope.add(disposable)` 接收 `Disposable` 或者清理函数；
`ctx.scope.defer(fn)` 就是帮你把任意清理函数包进作用域。重复释放也没事，安全的。

## 5. 权限和错误处理

除默认只读权限外，插件使用的能力都要在 `examaware.permissions` 中声明。建议使用
`PluginPermissions` 常量做权限判断：

```ts
import { PluginApiError, PluginPermissions, defineMainPlugin } from '@dsz-examaware/plugin-sdk';

export default defineMainPlugin({
  async activate(ctx) {
    if (!ctx.permissions.has(PluginPermissions.Network.Http)) return;
    try {
      await ctx.api.network.getText('https://example.com/ping');
    } catch (error) {
      const apiError = PluginApiError.from(error, 'my-plugin.network');
      ctx.logger.error(apiError.code, apiError.message, apiError.details);
    }
  }
});
```

默认权限为 `control.read`、`time.read`、`logging.read`、`plugins.read` 和
`events.subscribe`。完整权限如下：

| 分组              | 权限                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------- |
| Player            | `player.start`、`player.control`、`player.observe`、`player.contribute`                                  |
| Control           | `control.read`、`control.manage`、`control.replace`、`control.policy`                                    |
| Files             | `files.dialog`、`files.read`、`files.write`、`files.watch`                                               |
| Windows / App     | `windows.open`、`windows.manage`、`app.configure`、`app.settings.read`、`app.settings.write`、`app.quit` |
| UI                | `ui.contribute`、`ui.notify`                                                                             |
| Network           | `network.http`、`network.websocket`、`network.tcp`、`network.udp`、`network.listen`、`network.local`     |
| HTTP / Cast       | `http.routes`、`http.configure`、`cast.read`、`cast.share`、`cast.send`、`cast.configure`                |
| Time / Deep links | `time.read`、`time.synchronize`、`time.configure`、`deep-links.register`、`deep-links.dispatch`          |
| Logging / Plugins | `logging.read`、`logging.configure`、`plugins.read`、`plugins.manage`、`plugins.install`                 |
| Services          | `services.provide`、`services.consume`                                                                   |
| Commands / Events | `commands.register`、`commands.execute`、`events.publish`、`events.subscribe`                            |

以下权限会在安装时显示确认弹窗：`control.manage`、`control.replace`、
`control.policy`、`app.settings.write`、`app.quit`、`network.websocket`、`network.tcp`、
`network.udp`、`network.listen`、`plugins.manage` 和 `plugins.install`。更新插件新增这些权限
时也会再次确认。

API 错误使用统一的 `PluginApiError`。常见错误码包括 `permission-denied`、
`invalid-argument`、`invalid-config`、`not-found`、`conflict`、`cancelled`、`timeout`、
`network-error`、`io-error` 和 `internal-error`。判断错误类型时使用 `code`，不要依赖错误
文本。

## 6. 开发约定

- 所有宿主能力都从 `ctx.api` 调用，不直接访问 Electron、`window.api` 或内部 IPC。
- command、event、service 和 RPC 协议放在 shared contracts 文件中，并使用
  `createPluginTokens()` 创建强类型 token。
- `services.provide/use` 只用于同进程；跨进程使用 `exposeRpc/rpc`。
- UI 贡献写在 renderer 入口；HTTP 路由、深链处理器和自定义集控提供者写在 main 入口。
- API 返回的会话、窗口和提供者句柄在不再使用时应释放。
- 考试配置先通过 `exams.parse/validate`，或交给 `player.prepare/start*` 的统一校验流程。

开发时由 TypeScript 推断参数和返回类型。完整字段可查看 `ExamAwareMainApi`、
`ExamAwareRendererApi`、`PlayerStartOptions`、`ControlProvider` 以及各领域的 `*Api` 接口。
